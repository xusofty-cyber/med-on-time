# 多语言（i18n）技术定版与落地口径

> 定版：2026-10-30（第三批续·技术对齐欠账闭环）。语言锁定：简体中文（zh-CN，源语言）、
> 繁体中文（zh-TW，**台湾用语**）、English（en）。与 UI 规范 V1.0、DB V1.2 的 locale 口径
> （内容类表 locale 列：zh-CN / zh-TW / en）保持一致。
> 翻译流程口径（既定裁定）：机器初稿 + 人工校对，不强制医学审校。

## 各端选型

| 端 | 方案 | 说明 |
|---|---|---|
| Web（React） | 自研类型化字典模块 `apps/web/src/lib/i18n/` | zh-CN 为事实源；zh-TW/en 以 `Record<keyof typeof zhCN, string>` 约束键集合，**漏译在编译期报错**；运行时零依赖（与现有 store/api 的零依赖风格一致）。`tr()` 命令式翻译 + `useT()` 组件订阅；语言存 localStorage `mot.locale`，默认 zh-CN |
| Admin（React + antd） | antd 官方 locale（zh_CN / zh_TW / en_US）+ 同款类型化字典 | 组件库文案走 ConfigProvider locale；业务文案走自研字典（`apps/admin/src/i18n/`），约束方式同 Web |
| 微信小程序（Taro） | 同款类型化字典（移植 Web 运行时，存储改 Taro Storage） | 词条可与 Web 共用键名；平台 API 差异只在运行时适配层 |
| Android | 平台资源 `strings.xml`（values / values-zh-rTW / values-en）+ 逐应用语言（AppCompat per-app locale） | 系统标准方案；语言切换不依赖应用内字典 |
| iOS | `Localizable.strings`（zh-Hans / zh-Hant / en） | 系统标准方案；跟随应用内选择并写回偏好 |
| 桌面（Electron） | 复用 Web 词条与运行时 | 壳内即 Web 渲染，语言与 Web 同步 |

选型理由：不引入 i18next 等重型框架——本仓各端均为轻量自研状态/请求层，类型化字典
能在编译期拦截漏译（比运行时缺失回退更可靠），且词条文件是纯 TS 对象，便于
机器初稿批量生成与人工校对 diff。

## 词条规范

- 键名：`<域>.<条目>`，域包括 common / nav / auth / enum（枚举标签）/ today / plan /
  member / ehr / stock / adherence / notification / settings 等页面域。
- 占位符：`{name}` 形式，由 t(key, params) 插值；禁止在词条里拼 HTML。
- 枚举标签统一走 `enum.*`，各端 dict 层（Web 为 lib/dict.ts 的函数式标签）现取现译，
  禁止再新增静态中文标签常量。
- 繁体一律台湾用语：登入/登出、設定、訊息、簡訊驗證碼、掃碼、QR Code、錠劑、
  檢視、儲存、資料、品質 等；简繁同形词也要过一遍台湾口径（如「屏幕→螢幕」）。

## 范围与边界

- 本期范围：各端**界面文案**（含枚举标签、提示 toast、表单校验文案）。
- 不在本期：后端返回的业务错误 message（仍为简体中文，由服务端后续按请求 locale 处理，
  已登记为后端待办）；药品说明等内容数据（走 DB locale 内容组机制，非 UI 词条）；
  通知模板内容（DB notification_template 已有 locale 维度，按模板侧推进）。
- 服务端内容语言：通知模板/知情同意等内容类数据按 DB V1.2 的 (code, channel, locale)
  与内容组机制取数，与本文件 UI 词条互不替代。
