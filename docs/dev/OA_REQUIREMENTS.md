## 1. 定位与目标

### 1.1 一句话定位
订阅号是 MedOnTime 的**内容与入口阵地**，不是提醒通道：负责把用户领进小程序、教会用户用、把重要公告送到用户眼前；**实时服药提醒仍由小程序订阅消息承担**。

### 1.2 为什么不是提醒通道（能力事实，先于愿望）
| 能力 | 个人订阅号（未认证） | 对提醒的意义 |
|---|---|---|
| 模板消息 | ❌ 无（服务号专属） | 不能做结构化到点推送 |
| 群发消息 | ✅ 每日 1 次 | 折叠在「订阅号」文件夹、无强提醒，不可用于到点服药提醒 |
| 自定义菜单 | ✅ | 可直跳小程序（需先关联）——核心价值 |
| 自动回复（关注/关键词/收到消息） | ✅ 基础版 | 可做自助指引 |
| 图文素材与草稿 | ✅ | 指南、公告、科普的载体 |
| 图文内嵌小程序卡片 | ✅（关联后） | 内容 → 小程序的转化路径 |
| 用户管理（备注/标签） | ✅ 基础版 | 支持分人群群发 |
| 数据统计（关注/图文阅读） | ✅ 基础版 | 运营复盘依据 |
| 网页授权（OAuth） | ❌ 无（需认证） | 公众号内 H5 无法静默识别用户 |
| UnionID 归一 | ❌ 现阶段不可用 | 与小程序的用户身份**不能自动打通**（见 §5.2） |
| 客服消息接口（48h 主动下发） | ⚠️ 以后台实际权限为准（见 §8 核查清单） | 不作为设计依赖 |

### 1.3 目标（可验收）
- G1 新关注用户 3 步内能打开小程序并完成首次计划创建（路径：菜单/欢迎回复 → 小程序 → 指南图文兜底）。
- G2 每次版本更新/维护/功能上新，24 小时内有一篇公告图文发出（走 §6.3 审批流）。
- G3 沉淀一套常驻内容：使用指南 1 篇、常见问题 1 篇、用药安全科普栏目（双周 1 篇，医学表述过审口径见 §7）。
- G4 运营数据周维度可复盘：新增/取关、图文打开率、菜单点击（后台统计口径）。

## 3. 功能需求

优先级：P0 上线即需 / P1 首月内 / P2 常态化后。

### F1 自定义菜单（P0）
三级结构定版（2026-10-23 已定，素材已备 `~/workspace/medontime-oa/`）：
| 一级菜单 | 类型 | 目标 |
|---|---|---|
| 打开小程序 | 跳转小程序（未关联时退化跳转网页 https://mot.ulife.vip） | AppID wxfc47179d51798ba2，页面 pages/index/index |
| 使用指南 | 图文消息 | F3 的指南草稿素材 |

- 规则：菜单变更即全量生效；改菜单前先在测试关注号验证跳转；小程序未正式发布前，菜单跳小程序走体验版不可达风险须知——**菜单正式启用时机与小程序提审发布对齐**（发布前菜单可先配好但不宣传）。
- 验收：三台不同机型点击均达目标页；未关联状态下退化链接可用。

### F2 自动回复（P0）
- 关注后自动回复（定版文案已备）：欢迎语 + 三步上手 + 指南入口提示。
- 关键词回复（P1）：「提醒」→ 如何开启订阅提醒图文链；「授权」→ 照护授权说明；「客服/反馈」→ 反馈方式说明；「药盒/拍照」→ 拍照录入说明（功能上线后启用）。
- 收到消息默认回复（P1）：致谢 + 指引菜单/关键词，不承诺人工回复时效。
- 规则：回复内容只做功能指引，**不回答任何个体化用药问题**（统一话术引导就医/药师，口径同 §7 红线）。

### F3 常驻图文内容（P0 指南 / P1 其余）
- 《药准时使用指南》（已成稿）：注册登录 → 添加家人 → 添加计划 → 开启订阅提醒 → 打卡 → 照护授权 → 常见问题。
- 《常见问题集》：没收到提醒怎么办、换手机怎么办、药吃完了怎么补库存、如何取消计划。
- 图文规范：标题 ≤ 22 字；正文分段小标题；关键步骤配截图；文末固定放小程序卡片/二维码；字号照顾长辈阅读。
- 验收：指南内每个步骤与当前小程序 1.0.x 界面一致（版本变更时同步修订指南，列入发版检查单）。

### F4 群发公告（P1）
- 类型：版本更新、维护通知、功能上新、重要政策（如提醒方式变更）。
- 额度纪律：每日 1 次为硬上限——**公告攒批发送**，非紧急不单独占用；紧急停服通知例外。
- 流程（强制）：起草（草稿箱）→ 负责人确认 → 群发 → 次日看打开数据复盘。**任何人不得跳过确认直接群发**（含 AI 代理）。
- 分群：可用标签（F5）做定向（如仅家属向内容），默认全量。
- 验收：每篇公告有草稿留痕与发送记录；标题不含夸大疗效表述（§7）。

### F5 用户标签与备注（P1）
- 标签口径（≤ 6 个）：`患者本人`、`家属照护`、`来源-子女推荐`、`来源-视频号`、`已建计划`、`待激活`。
- 打标方式：运营手动（后台用户管理）；自动打标接口未认证不可用，不做设计依赖。
- 用途：F4 定向群发与 G4 数据分层。

### F6 小程序协同触点（P0/P1）
- 图文内嵌小程序卡片：每篇常驻图文至少 1 处卡片，直达对应功能页（指南 → 首页；拍照录入文 → 计划新建页）。
- 简介与头像：简介沿用「按时服药，家人安心」；头像与小程序同 logo（已一致）。
- 视频号联动（P2）：已绑定 xSofty；科普短视频与图文互引，公众号简介挂视频号入口按后台能力为准。

### F7 数据统计与复盘（P1）
- 周报口径：新增关注、净增、取关、图文阅读/分享、菜单点击（后台「数据统计」导出留档至项目文档）。
- 触发动作：连续 2 周净增为负 → 复盘最近内容与菜单；图文打开率 < 5% → 改标题/封面策略。

## 4. 与小程序的联动设计

### 4.1 跳转链路
菜单（F1）/ 图文卡片（F6）/ 自动回复文字链（F2）三路并行，目标一致：小程序 pages/index/index 或功能页。关联小程序为前置动作（后台「小程序管理」发起，小程序管理员确认——**两号管理员非同一微信（见 §8），需负责人分别在两个管理员微信上操作**）。

### 4.2 身份打通（现状与边界）
- 现状：未认证订阅号拿不到 UnionID；且公众号管理员与小程序管理员为不同微信主体。**结论：现阶段不做自动身份归一。**
- 替代路径（产品内闭环）：小程序内「绑定微信」已上线（openid 绑定）；公众号侧只负责把人送进小程序，身份在小程序内完成。
- 升级后（§9）：服务号认证并绑定同一开放平台后，再评估 UnionID 归一与模板消息直达打卡页。

### 4.3 提醒分工（全渠道口径，避免用户误解）
| 通道 | 承担 | 不承担 |
|---|---|---|
| 小程序订阅消息 | 到点服药提醒（攒授权） | —— |
| 原生 App（安卓/桌面） | 弹窗 + 闹钟/语音强提醒 | —— |
| 订阅号 | 入口、教学、公告、科普 | **任何到点提醒** |
| 短信（待网关） | 兜底提醒 | —— |
指南与欢迎回复中必须明示这一分工，防止用户以为「关注了公众号就会提醒吃药」。

## 5. 内容与合规红线

1. **不诊断、不开方、不荐药**：科普只讲通用用药安全常识（如漏服处理原则、储存常识），个体问题一律引导就医/咨询药师。
2. **不承诺疗效**：公告与科普禁止「有效率、治愈」等表述；新功能描述只讲功能事实。
3. **医学表述审核**：科普类图文发布前须负责人逐篇确认；条件具备后引入药师审读（与 AI 线的外部医学审校口径一致）。
4. **隐私**：图文案例不得使用真实用户数据；截图须脱敏（无真实姓名/药名组合可识别信息）。
5. **群发纪律**：见 F4 审批流；AI 代理可起草、备素材，**不得代发群发**（负责人 2026-10-23 夜令）。

## 6. 非功能需求
- **可用性**：菜单/自动回复配置变更后 10 分钟内自测（关注号实测截图留档）。
- **安全**：公众号管理员微信与小程序管理员微信分离现状保留记录；后台登录只走负责人扫码；不向第三方授权代运营（授权管理页保持空白）。
- **成本**：全部功能零付费实现；不买群发工具、不投广告。
