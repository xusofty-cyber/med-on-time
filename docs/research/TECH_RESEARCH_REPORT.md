# 药准时 MedOnTime 技术预研报告

> 版本：V1.0（2026-10-20）| 状态：待评审
> 预研目标：探索可集成的**AI 问诊/对话系统**与**药品系统**（开源与商用），给出选型建议、分期集成路径与 POC 计划。
> 边界声明：产品定位为 **AI 健康助手**（健康咨询 / 用药科普 / 报告解读 / 就医引导），不做疾病诊断结论；本报告所有候选系统的输出均须经过安全规则层约束后才能触达用户。

---

## 1. AI 问诊 / 对话层

### 1.1 开源医疗大模型（可自托管，数据不出域）

| 模型 | 机构 | 规模 / 基座 | 开源与许可 | 中文医疗能力 | 评估 |
|---|---|---|---|---|---|
| **华佗GPT-II (HuatuoGPT-II)** | 港中文深圳 / 深圳市大数据研究院 | 7B / 13B / 34B | 权重开源；官方声明**不可直接利用结果进行诊疗**；商用许可须单独核查 | 通过执业药师等考试；中文医疗基准领先 | **重点候选**，综合能力最强的开源医疗模型 |
| **京医千询** | 京东健康 | 全面开源（参数、数据构造、训练、评测代码） | 已宣布全面开源；商用许可须单独核查 | 背靠京东互联网医院真实问诊数据与供应链闭环 | **重点候选**，商用场景背书强，重点核查许可条款 |
| 本草 BenTsao | 哈工大 SCIR | LLaMA LoRA 微调 | 开源 | 2023 年水平 | 规模小、停滞，仅作参考 |
| 扁鹊 BianQue | 华南理工大学 | ChatGLM-6B | 开源 | 多轮问诊对话 | 规模小、停滞，仅作参考 |
| DISC-MedLLM | 复旦大学 | 13B | 开源 | 医疗对话重构数据 | 维护弱，仅作参考 |
| DoctorGLM | 上海科技大学 | ChatGLM | 开源 | 通用医疗问答 | 规模小、停滞，仅作参考 |

结论：主力候选为 **华佗GPT-II** 与 **京医千询**；其余 2023 年小模型只保留为架构参考。

### 1.2 商用医疗大模型 API（上线快，P1 可验证）

| 厂商 | 产品 | 接入方式 | 备注 |
|---|---|---|---|
| 科大讯飞 | 星火医疗大模型 | 讯飞星辰 MaaS / 开放平台 | 医疗数据飞轮成熟（病历采纳量计费模式已跑通） |

行业背景：全国已发布 352+ 个医疗大模型，模型过剩但跑通"部署—使用—付费"闭环的产品稀缺；选型时关注**可解释性、数据合规、计费模式**，不只看评测分数。

### 1.3 症状分诊引擎（谨慎）

| 系统 | 资质 / 能力 | 定价 | 评估 |
|---|---|---|---|
| **Infermedica**（波兰） | 欧盟 MDR IIb 类医疗器械认证；1800+ 症状 / 900+ 疾病；94% 分诊准确率；20+ 语言 | 企业级（小机构约 $10k+/年起） | 能力最强但**三重问题**：境外服务器导致国内用户健康数据出境风险；其器械认证在中国不适用；价格高 |
| ApiMedic（瑞士） | 症状自查 API，开发者友好 | 较便宜，有免费测试 | 能力弱于 Infermedica，可做轻量备选 |

结论：**不做正式分诊功能**。P2 以"大模型 + 安全规则"实现轻量风险提示与就医引导，不出分诊结论，避开医疗器械注册与数据出境两个雷。

## 2. 药品系统层（对药准时最关键、风险最低）

| 数据源 | 内容 | 接入方式 | 费用 | 评估 |
|---|---|---|---|---|
| **丁香园用药助手** | 7 万+ 份说明书（覆盖国内 99% 药品）；2000+ 成分合理用药库（相互作用、特殊人群、妊娠哺乳分级、黑框警告） | 商务数据授权（无公开自助 API） | 商务洽谈 | **质量国内最好**，正式运营阶段首选授权源 |
| **聚合 API 市场**（如腾讯云市场药品查询 API） | 近 10 万种药品，可按药名 / 批准文号 / 成分检索 | 自助 API | 便宜 | 可快速打底（P0），但质量参差，上线前须抽检 |
| **药智数据** | 商用药品数据服务 | 商务 | 商务洽谈 | 丁香园的备选授权源 |
| **NMPA 国家药监局药品数据** | 官方批准文号 / 上市药品信息 | 公开查询（无 API） | 免费 | 权威基准，用于批准文号核验与数据清洗 |
| **DrugBank** | 药物相互作用金标准 | 免费层（无严重程度分级）；商用付费授权 | 付费 | 相互作用 P1 评估授权 |
| **openFDA** | 美国说明书 / 不良事件 / 召回（英文） | 免费 API | 免费 | 英文对照与安全信号参考 |
| **RxNorm (NLM)** | 药名标准化 / INN 通用名对照 | 免费 API | 免费 | 补齐三语方案中英文药品名与 INN 映射 |
| **DailyMed (NLM)** | FDA 说明书全文 | 免费 | 免费 | openFDA 的补充 |

结论：**P0 自建打底 + P1 商务授权**。药品库 schema（数据库设计 V1.1）已预留说明书结构化字段与多语言字段，数据层接入即插即用。

| 项目 | 规模 | 说明 | 评估 |
|---|---|---|---|

## 4. 许可、合规与风险清单

1. **开源模型商用许可**：华佗GPT-II、京医千询在商用前必须逐条核查其开源许可（是否允许商用、是否要求署名/相同方式共享）；保留法务确认记录。
2. **药品数据授权**：丁香园 / 药智 / DrugBank 均需签署数据授权协议，明确字段范围、更新频率、转授权限制；聚合 API 注意其数据源的二次分发条款。
3. **数据出境**：健康医疗数据属重要数据；任何境外 API（如 Infermedica）接入前必须完成数据出境安全评估，否则禁用。
4. **医疗器械注册**：若未来上线正式"症状分诊 / 辅助诊断"功能，须按 NMPA 医疗器械注册路径申报；当前"健康助手 + 风险提示"定位可规避。
5. **药品功效表述**：AI 输出与药品介绍页的文案须符合广告法与药品管理法（不做疗效承诺），安全规则层强制约束。
6. **模型幻觉**：医疗问答必须走 RAG（药品库 / 说明书 / 知识库） grounding；无依据回答一律转人工建议或拒绝回答并引导就医。

## 5. 推荐集成路径（分期）

- **P0（药品库打底）**：聚合 API + NMPA 公开数据填充药品库；RxNorm 做英文名 / INN 对照；i18n 药品多语言字段同步填充。
- **P1（AI 基础版上线）**：AI 网关（已设计）先接一家商用 API 跑通全链路（安全规则、审核、计费）；同步启动华佗GPT-II 7B 与京医千询自托管 POC，对比效果 / 延迟 / 成本；洽谈丁香园（或药智）数据授权；评估 DrugBank 相互作用授权。
- **P2（增强）**：根据 POC 结果决定是否切换自托管；引入知识图谱增强 grounding；相互作用校验上线；分诊仍只做风险提示。

与现有架构的对接点：`ai_model_config` 表已预留多模型路由字段；`ai_safety_rule` / `ai_output_review` 承接安全约束；药品库表承接说明书结构化字段。

## 6. POC 计划

### POC-1：药品数据打底
- 目标：验证聚合 API 数据可用性。
- 方法：抽取 200 个常用药，核对说明书关键字段（用法用量、禁忌、相互作用）准确率。
- 通过标准：关键字段准确率 ≥ 99%，否则换源或加人工审核流程。

### POC-2：AI 对话模型选型
- 候选：华佗GPT-II 7B（自托管） vs 京医千询（自托管/评估） vs 商用 API（讯飞星火医疗）。
- 评测集：自建 120 题（药品咨询 40 / 报告解读 40 / 风险提示与就医引导 40），含 20 题安全红线题（必须拒绝或转介）。
- 指标：医学准确性（医生盲评）、安全规则拦截率（红线题 100%）、幻觉率、P95 延迟、千次成本。
- 通过标准：准确性 ≥ 商用基线、安全拦截 100%、幻觉率 < 5%。

### POC-3：相互作用数据
- 方法：DrugBank 试用数据 vs 说明书禁忌字段，抽 100 组常用复方做覆盖率对比。
- 通过标准：覆盖率 ≥ 95% 或明确补齐路径（人工药师审核）。
